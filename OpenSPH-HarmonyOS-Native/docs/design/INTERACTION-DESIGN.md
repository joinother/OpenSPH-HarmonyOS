# 星体实验室交互设计

> 类型：用户流程与界面契约；设计日期：2026-09-09（Asia/Shanghai）；审视基线：0.56.0。用户明确要求重新审视操作逻辑、名称与布局；本页保留 0.56.0 的审视依据；0.57.0 已接入首批整改，完整方案未经新用户试用。开发顺序仍在 [唯一执行路线](../reference/PRODUCT-ROADMAP.md)，不新建第二条功能队列。

## 要让用户形成什么认识

这是一个可以摆放天体、改变运动、观察相互作用的空间。星图是工作台，天体是操作对象，时间条控制当前模拟。用户不需要先理解 SPH、示踪点、求解器或预松弛，才能开始使用。

每个状态都要回答五个问题：**我在哪里；选中了谁；现在是否在运行；下一步可以做什么；这次操作会不会丢掉当前结果。** 需要重新计算、只能观看回放、尚不能继续的限制，在相关操作旁直说，不能只藏在介绍末尾。

对三种改法的取舍：只换标题不能解决操作含义变化；增加长篇新手教程会迫使用户记住现有混乱；采用按任务组织、按对象显示操作、按状态给出下一步的方式。短引导在用户首次做该动作时出现，能够关闭；熟悉后仍使用同一界面。

## 已核对的问题

来源：[主题配置](../../entry/src/main/ets/common/ExperimentCatalog.ets)、[页面与共享动作](../../entry/src/main/ets/pages/Index.ets)、[布局规则](../../entry/src/main/ets/common/WorkspaceLayout.ets)、[R01 实测](../reference/CONTINUOUS-COLLISION-ACCEPTANCE.md)及 [本轮只读记录](../evidence/ux-audit-2026-09-09.json)。以下是设计审视与用户反馈，不是新用户研究的统计结果。

| 问题 | 当前证据 | 用户容易产生的误解 | 设计决定 |
| --- | --- | --- | --- |
| 标题省略对象与变量 | “反转一片星系”“已有裂隙，还能撑住吗” | 反转画面还是轨道；是否真的画出裂纹；怎样才算撑住 | 主标题写对象与操作，问题句只作副标题；不使用模型未实现的形态作承诺 |
| 物理演示与技术检查混在一起 | “碰撞”分类含粒子预算对照、预松弛、静止岩球、星系 | 每个都是可以直接玩的碰撞实验 | 场景按用户目标分类；数值检查进入单独的“模型验证”，不挤占推荐列表 |
| 参数面板承担过多职责 | inspector 同时包含 presets、材料、轨道、外观等 | 改光照也会重算；切换实验只是改显示 | 对象属性、模拟设置、显示设置与场景选择分开 |
| 观察含义太宽 | 近看、观察面板、团块跟随、曲线都叫观察相关词 | 点“观察”应该直接看到天体，实际却进入数据面板 | 近看叫“靠近查看”；曲线入口叫“数据”；显示颜色放“显示” |
| 同屏有两套播放概念 | 本轮已完成星系画面同时出现“播放回放”“开始实验”“最新” | 开始会继续还是重跑；两个播放有什么不同 | 根据实时／回放状态只突出一个播放动作；重跑独立放置 |
| 完成后仍叫开始 | simulationLabel 在非轨道 completed 回退“开始实验” | 会从当前时刻继续 | 本段结束主操作是“查看回放”；重新计算明确叫“从头重跑” |
| 保存的对象不清楚 | project.save 保存初始配方；replay.save 保存观察记录，部分轨道可续算 | “保存实验”就是保存当前宇宙进度 | 分为保存设置、保存回放、保存进度，按真实能力提供 |
| 同一个返回指向不同层级 | closeSurface、ui.back、impact.return、video.close | 返回只是收菜单，却可能回到另一个世界状态 | 通用返回只退界面一层；世界切换必须写出目的地和后果 |
| 主按钮会变成世界切换 | 局部运行结束后 mainSimulationAction 变为 impact.return | 一直点同一按钮可以接着看碎片演化 | 完成态不把“返回原轨道”伪装成继续；R02 起统一状态文案 |
| 操作只有禁用，没有就近原因 | 局部撞击按钮依赖暂停、草稿、事件及尺寸等多个条件 | 按钮坏了，不知道缺哪一步 | 就近提供一个可解决的原因和动作；详细限制展开查看 |
| 小屏被固定控制区挤压 | 360×780 vp、零避让、开面板时代入布局公式，构图高度仅 144 vp | 打开菜单后丢失操作对象和位置感 | 放置时收起完整时间轴，面板默认短展开；对象保持可见 |
| 小字承担关键后果 | 多处限制使用 10／11 号字，底部提示单行截断 | 看见“确认”，看不见“从零开始” | 会重算／不能续算等核心信息提升为正文；完整错误可展开 |
| 不同模型都装进同一层界面 | SPH、轨道、环、星系使用不同时间单位和能力 | 任何星体都能碰撞、任何模式都可持续运行 | 区分“轨道沙盒”“局部撞击演示”“星系演示”；不要求用户识别算法名称 |

上述 144 vp 是代码推导的构图安全区域，不是本轮手机实拍，也不表示原生画面被裁成 144 vp。本轮只读现场为已完成的星系场景，约 707×773 vp，没有切换场景、拖动时间、打开菜单或改变用户配置；完整现场与截图留在私有 build。

## 用户怎样开始

第一次进入显示一个暂停的简单恒星与岩体场景，附一行“点选天体，或加入一个新天体”。提供“加入天体”和“选择场景”；不默认打开技术参数。此初次入口随 R03 接入，不在当前版本假装已改变。

以后进入：只有存在已验证可续算的记录才显示“继续上次模拟”；否则明确显示“打开上次回放”或“按上次设置重新开始”。不得从配方重新生成后称为恢复进度。

场景选择采用四个容易区分的分组：搭建系统、岩体碰撞、星系演示、我的保存。技术预设置于“更多 → 模型验证”；现有内容不删除，旧 ID 和保存记录仍可打开。首次推荐只露出少量代表内容，其余可按类别寻找。

一张场景卡只放：具体名称、真实画面或标注清楚的示意、能做的一件事、关键能力限制。例如“岩石快速相撞 / 改变速度，观察材料分散 / 局部演示，结果暂不能回到轨道”。粒子预算、压力模型与长段说明放详情；会影响用户预期的限制不能藏起来。加载前先看详情，再“打开场景”；有未保存结果时提供实际可用的保存方式与放弃选项。

## 主工作区与布局

| 位置 | 内容 | 不应混入的内容 |
| --- | --- | --- |
| 顶部轻工具栏 | 场景名称、选择场景、显示、更多 | 模型参数、全部统计、重复播放按钮 |
| 中央星图 | 选择、转动、缩放、放置预览；选中对象有名称与描边 | 常驻教学长文、遮住目标的弹窗 |
| 对象操作条 | 选中对象名称；靠近查看、编辑、向它添加 | 与对象无关的全局设置 |
| 底部时间条 | 当前状态、带单位的时间、唯一开始／暂停动作、速度 | 同时播放模拟和播放回放的两个主按钮 |
| 底部“加入天体” | 自由创建入口，当前阶段不能加入时解释原因 | 仅藏在参数面板内的加入入口 |
| 当前任务面板 | 放置、编辑、数据三者一次只展开一个 | 多层面板叠加和重复确认按钮 |
| 更多 | 保存、录制、模拟设置、帮助、模型验证 | 高频选中、暂停、放置操作 |

手机上对象操作条在底部时间条上方；进入放置／编辑时以任务条替代完整历史时间轴，保留暂停标识及当前时间。详细设置可以继续展开，但默认不超过可用高度的 40%；这是拟定布局预算，需实机校验。键盘出现时收起次要操作并滚动当前字段，不缩小字体硬塞。横屏矮窗口优先紧凑侧面板，不能只依赖宽度断点。

宽屏使用同一套操作名，当前任务放在侧面板，宽度先以 280–340 vp 评估；若剩余星图太窄则转为短面板。浏览时目标为可用画面至少 70% 不被控件覆盖，放置时至少保留一半连续可操作区域和完整目标；目标是布局验收条件，尚非实测成绩。折叠、旋转只重排布局，保留选择、草稿、时间、相机与任务步骤。

星空延伸到窗口边缘，文字和操作有局部半透明衬底保证可读性。悬浮不等于全部透明，也不等于每个文字都包成胶囊。主操作、普通按钮、开关、状态文字分别有稳定外观；颜色不能代替“运行／暂停／回放”等文字。采用统一圆角层级、间隔和正文大小，先解决结构与阅读，再调装饰。

拟采用 180–240 ms 的面板转场，可中断并遵循减少动态效果设置；一次只推动当前任务面板。选中对象保持位置线索，用户拖动即接管镜头。时间推进与动画独立，不能靠缩放或淡出隐藏世界重载。这些动画参数是待验证设计值。

华为的 [布局基础](https://developer.huawei.com/consumer/cn/doc/doccenter-ux-design/design-layout-basics-0000001795579413)强调按窗口宽高与比例响应、移动优先、保留安全区，并在折叠／旋转时维持布局完整。本项目据此制定以上空间与状态规则；面板比例、操作分组和动画时长是本项目设计取舍，并非华为规定数值。本轮华为 MCP 请求返回 400，改读官方网页；界面用语、工具栏和半模态专题正文加载失败，未计作已读依据。

## 五条必须容易走通的路径

### 看一颗天体

点天体 → 出现名称和对象操作条 → 靠近查看 → 返回全景。第一次点选只选择，不自动飞过去；再次点选也不触发编辑。拥挤目标可从“天体列表”按名称选择。查看、选择、开关外观不会重算；靠近后仍保留太阳及其他对象。手势提示只在首次出现，鼠标、触屏和 CLI 对应同一语义动作。

### 加入一颗天体

加入天体 → 选类型 → 选加入方式 → 在星图调位置／方向 → 确认加入。

加入方式固定为“绕目标运行”“自由投放”“朝目标发射”。已有选中对象时默认使用它，界面始终显示目标名称；没有目标时要求先选择，不能默默绑定恒星。向目标添加卫星，是“绕目标运行”的快捷入口，不另建一套放置界面。绕行只提供初始轨道建议，不能暗示永远稳定。

预览显示半透明天体、目标标记、起点和速度箭头；轨迹若只是近似就标“参考轨迹”，不能显示未经计算的命中保证。默认只显示尺寸、距目标距离、速度等本方式必需字段；精确向量、倾角、密度进入高级设置。图面拖动与数值输入双向同步；拖动位置和拖动空白旋转镜头必须有不同命中区域，另提供位置锁定，不能要求用户猜手势。

进入预览时暂停当前模拟，并显示“放置中 · 时间已暂停”；取消只删除草稿，恢复进入前的运行／暂停状态。确认不自动播放，停在加入时刻并选中新天体，提示“已加入，点击继续”。坐标和速度以哪个对象为参照写在字段旁；半径／直径、中心距／表面高度明确标注，切换单位不改变实际数值。

撞击后的质量继承和提交尚未实现；R06 前不能在局部结果上提供看似可用的“继续添加”。达到容量时显示“当前场景最多支持 8 个天体，删除一个后可继续加入”，放置草稿保留，不隐式删除天体。

### 朝选中天体发射

点目标 → 向它添加 → 朝目标发射 → 调起点、方向和速度 → 确认加入 → 继续时间。目标操作条同时提供“朝它发射”的快捷动作，复用上述草稿与确认。不要先让用户进入实验库猜哪张卡片代表撞击。

接触后进入明确的事件状态。R02 第一阶段提供“计算岩石撞击”“按球体碰撞继续”等实际支持路径，并紧邻说明局部结果目前不能回到轨道；环境模型选择收入高级设置，默认选择及适用范围必须由物理判据确定。未来 R04–R06 通过后再简化为连续撞击流程，不能仅改标签就显示“碎片继续运行”。

### 改一个条件作对照

查看结果 → 对照 → 复制当前设置 → 明确显示只改的变量 → 从头运行新副本。原结果保留为参照；不能让“切换对照”无提示替换整个当前世界。基础结果先显示画面、可追踪的材料去向和一项所选变量；需要时再打开数据曲线。两次实际初值差异可查，比较同一物理时刻，粒子预算对照属于模型验证。

### 保存并回来

保存入口先写清保存内容。可续算的轨道状态才提供“保存进度”，并标明“可继续模拟”；目前只能保存局部结果的 SPH 显示“保存回放 · 仅观看”；project 配方显示“保存设置 · 从头运行”。视频属于导出画面，不作为保存进度的替代。

R02 只承诺其通过验收的稳定事件边界恢复；中途 SPH 求解续算仍不支持。R06 接续存档通过后才将“保存进度”扩展到撞击后的世界。保存成功说明保存类型及时间，失败保留现场并提供重试。载入显示其类型，旧档不能因为缺字段被误标可续算。

## 时间、返回与编辑的统一规则

| 用户所处状态 | 时间区主操作 | 次要操作与提示 |
| --- | --- | --- |
| 初始暂停 | 开始模拟 | 当前时间与单位；可编辑／加入 |
| 正在演化 | 暂停 | 速度以“每秒推进 1 天”等可理解单位显示；需要时提示目标与实际速度差异 |
| 可继续的暂停状态 | 继续模拟 | 不清零时间，不重新应用初始参数 |
| 正在准备 | 取消准备 | 明确阶段，不让“暂停”承担取消重建的含义 |
| 本段计算结束 | 查看回放 | “本段结束于 800 百万年”等完整时间；从头重跑为独立次要动作 |
| 正在看历史 | 播放回放／暂停回放 | “回放”持续可见；回到当前状态写明目的地；只有支持分支续算时提供“从此刻继续” |
| 局部撞击演示结束 | 查看回放 | R06 前显示“返回原轨道 · 不带入撞击结果”；不能叫继续世界 |
| 冷载入局部回放 | 播放回放 | “仅供观看，不能继续计算”；没有父世界时不显示返回原轨道 |
| 出错 | 重试对应操作 | 显示具体原因，完整信息可展开；不要静默从零开始 |

“关闭”收起面板，不改物理状态；“取消放置／取消编辑”丢弃本次草稿；“返回全景”只改镜头；“放弃局部撞击”依 R02 回到约定事件检查点；“从头重跑”明确清零本次演化。系统返回依次退出当前任务子页、处理草稿、收起面板、退出近看；仅在丢失有效编辑／结果时给保留与放弃选择，不给每个按钮都加确认。

显示设置立即生效且可还原，不需要“应用并开始”。对象初始参数在“编辑设置”中先形成草稿，当前版本必须重算的操作明确叫“应用设置并从头运行”。在暂停帧修改当前对象并接续属于待实现能力，不能把现有初值编辑重命名为实时编辑。用户打开别的面板不会偷偷应用草稿。

| 先准备，再相撞 | 先准备岩石，再撞击 | 模型验证；详情说明定时预松弛不是达到平衡 |
| 静止岩球，会一直静止吗？ | 静置岩石 | 模型验证；观察自引力下的变化 |
| 撤去阻尼之后 | 先准备岩石，再静置 | 模型验证；正文解释减振和自由演化 |
| 两条潮汐尾 | 两个星系相遇 | 星系演示；是否形成明显长尾由实际计算决定 |
| 反转一片星系 | 让一个星系反向旋转 | 星系演示；是反向自转，不是反转镜头／时间／相遇轨道 |
| 恒星也能拉动星系 | 恒星之间相互吸引 | 星系演示中的高级对照 |
| 无质量恒星 · 对照 | 忽略恒星之间的引力 | 高级对照；不是宇宙中存在无质量恒星 |
| 完整冷岩，相撞之后 | 撞击完整岩石 | 岩体碰撞；初始额外内能为零不等于绝对零度 |
| 预热岩体，同样一撞 | 撞击加热后的岩石 | 岩体碰撞；额外内能 1.7 MJ/kg，不换算未经验证温度 |
| 已有裂隙，还能撑住吗 | 撞击受损岩石 | 岩体碰撞；材料损伤参数 90%，不是 90% 质量已碎，更不是可见裂纹 |

其余高风险操作也统一：参数 → 分属对象编辑／模拟设置；观察面板 → 数据；专注 → 隐藏工具，并保留易找的“显示工具”；恢复主题 → 恢复初始设置；切换对照实验 → 用另一组设置作对照；最新 → 回到当前状态／回放末尾（由状态决定）；记录最大／最小 → 跳到已记录最大／最小值；隔离撞击 → 计算岩石撞击；含外部潮汐 → 计入周围天体的引力（高级设置，解释外场冻结）。

同一动作的界面标签、无障碍名称和 CLI 目录从同一处生成，稳定 ID 不随文案改变。标题可以吸引人，但控件必须用动词与对象；无依据的“稳定”“熔融”“月球生成”“完整宇宙”不用于结果承诺。

## 怎样进入现有路线

| 工单 | 必须一同落地的交互工作 | 验收结果 |
| --- | --- | --- |
| R02 | 首批命名与行为后果说明；实时／准备／完成／回放状态用语；保存类型、事件选择与返回目的地；统一动作文案来源 | 同一按钮不隐藏清零或世界切换；无父会话不说可返回；旧 ID 与保存兼容 |
| R03 | 主视口任务结构、对象操作条、统一放置三种方式、紧凑面板及跨屏状态连续；显示与数据入口分离 | 用户看得见目标，选中／近看／旋转不开新实验；放置与取消保留世界和草稿规则 |
| R04–R06 | 时间权威与真实可继续状态；残骸提交、再次加入和可续算保存 | 标签与实际演化一致；不会“写着继续，实际返回旧世界” |

用户本次明确要求后，不能再把所有操作清晰度问题推迟到 R07。R02／R03 自带基础交互整改；后续工单沿用同一契约。初次设计交付未提升版本。0.57.0 已落实 23 个主题标题、完成／回放主操作、旧事件入口防护、保存设置与冷载入提示；分类、对象操作条、面板布局、稳定事件存档与完整任务验收仍待落实，不能把整份设计标记完成。

## 验收任务，而不是“看着顺眼”

以下均待新界面实现后执行。本轮没有招募试用者或验证这些指标。

| 任务 | 用户应能独立完成／说明 | 程序与设备核对 |
| --- | --- | --- |
| 初次进入 | 30 秒内找到加入和开始；知道现在暂停 | 首屏无技术表单；必要操作有文字与无障碍名称 |
| 添加卫星 | 不翻参数面板，围绕选中对象放置，再取消一次 | 目标身份正确；取消不改变原向量和时间；确认只加入一次 |
| 朝目标发射 | 知道目标、起点、方向、速度，预览后确认 | 图面与字段一致；错误就近显示；不承诺虚假命中 |
| 近看与返回 | 能返回全景，知道只是换视角 | 不重算、不重置选择或时间；其他天体仍在 |
| 完成与回放 | 能区分观看、继续、重跑，点击前说对后果 | 状态表逐项断言；不会自动将无续算能力回放重算 |
| 保存与重开 | 能区分设置、回放、进度 | 按记录类型验证恢复；不把初始配方当当前状态 |
| 放置中旋转／折叠 | 不丢目标、草稿和当前步骤；键盘不挡确认 | 手机、折叠收起／展开、矮横屏、PC 窗口；物理世界保持不变 |
| 看懂一张实验卡 | 能说出对象、改变的条件及可观察内容 | 不把损伤当裂纹、不把反向自转当时间倒放、不把概念封面当实算结果 |

先进行内部任务走查，再在获得试用安排后找至少 5 位未参与开发的人执行；拟定门槛是至少 4 人不靠讲解完成主要任务，且无人因按钮含义不清而误清空结果。记录误点、退回、求助和对保存类型的理解，不用平均满意度掩盖严重错误。CLI 验证共享行为，真实点击、字体放大、焦点、遮挡和动效分别验证。
