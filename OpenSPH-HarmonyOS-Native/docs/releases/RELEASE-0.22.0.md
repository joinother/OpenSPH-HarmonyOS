# 0.22.0 · 可取消、可等待的连续镜头

> 类型：版本记录；版本：0.22.0；验证日期：2026-09-07（Asia/Shanghai）。本版为模拟器未签名交付。

## 行为变化

镜头过渡现在统一由原生渲染时钟驱动。物理暂停时仍能飞近、拉远或返回全景；连续切换天体时从当前姿态与构图继续。飞行期间出现“停在这里”，点击或拖动可接管镜头。打开天体编辑菜单保留当前远近视角，需要近看时单独选择“近看行星”。

之前 ArkTS 负责角度／缩放动画，原生层负责天体中心与表面过渡，CLI 只能看混合了面板构图的 cameraMoving。现在显式导航具有请求 ID，可查询排队、飞行、完成或取消；旧请求的取消不能影响后来的飞行。完成记录在对应帧成功提交后产生，窗口构图动画另行推进。

新增 `navigateCamera`、`getCameraMotion`、`cancelCameraMotion`，以及共用的 `camera.cancel` 动作。CLI 的 `--wait-camera` 和批次项 `waitForCamera:true` 等待本次请求，取消会明确失败退出。保留原 `setCamera` 接口；需要重新飞往同一目标时使用显式导航。完整参数和状态见 [CLI 指南](../CLI.md)。

## 实现与边界

- [镜头导航状态](../../entry/src/main/cpp/camera_navigation.h) 由渲染器持有并加锁；视口尺寸变化不主动取消，渲染表面重新创建时不随局部变量丢失。场景替换会隔离旧请求和旧天体权重，并忽略迟到的旧场景渲染帧，避免覆盖新导航。
- [构图插值](../../entry/src/main/cpp/camera_journey.h) 支持保留中间权重、重新指定目标和 0–3 秒时长。修正了上一次为零时长时，下一段旅程可能提前跳到新目标的边界。
- 手势中的连续姿态更新不生成大量导航请求；修正实际触摸验收中发现的高频更新挤掉取消记录的问题。当前请求与最近 32 条终结记录在进程内可查询，进程重启后旧 ID 不再有效。
- 取消只停止镜头过渡。运行中的天体继续运动，云层／行星外观自转仍遵循原设置；这不是冻结整个宇宙。云层等外观开关不会恢复已取消的过渡。
- 配方仍保存目标视点，不保存半途构图的混合权重、请求 ID 或动画进度；本版未改变存档格式。选择与跟随仍沿用现有 focus 语义，完整的观察参考系与独立选择模型继续留在后续路线。

本轮独立实现，没有移入 Celestia 代码、界面或素材，也未修改求解器、自引力、碰撞材料或环粒子模型。
