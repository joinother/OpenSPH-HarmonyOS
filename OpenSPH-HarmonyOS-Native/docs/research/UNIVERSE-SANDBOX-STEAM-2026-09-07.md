## 结论与本轮范围

最值得借鉴的是“把作品做成可重复游玩的实验”：一组行星和卫星可以整体保存与放置；好看的外观随对象保存；每个预设明确告诉玩家改变什么、观察什么，以及多久能看到结果。创意工坊的题材可拓宽实验库，而指南中繁琐的绕行操作应转成直接的编辑能力。

三条优先补充是：完整实验配方与子系统保存、赤道／轨道平面放置、相互独立的外观与物理预算。它们延续 [博客与论坛路线](UNIVERSE-SANDBOX-BLOG-FORUM-2026-09-07.md) 和 [Wiki 补充](UNIVERSE-SANDBOX-WIKI-2026-09-07.md)，不意味着现在已经具备月球形成或全宇宙碰撞。

## 对技术路线有影响的新证据

在 [opensph mod??](https://steamcommunity.com/app/230290/discussions/0/3493131640456884364/) 中，带开发者标识的 bshapiroalbert 于 2026-06-08 回复：团队已排除完整引入 OpenSPH，仍研究流体式碰撞；并提到 Pavel 的 SpaceSim 是非实时模拟器。该主题还保留了 2022 年较早的讨论。网页工具的旧缓存只有早期回复，本轮直接取得的公开 HTML 则包含 2026 年回复，证据保存其帖子时间戳 `1780927962`。

这条信息不能用于推断闭源实现，但会影响我们的安排：ArkUI 负责交互与状态，当前 C++ 求解器逐项验证；实时探索、有限分辨率碰撞实验、耗时计算后回放分别设置预算。先完成单体平衡、自引力和守恒／收敛测试，再谈具有科学意义的月球形成。不能因为 OpenSPH 可编译，就认为行星初态、材料、重力和可视化已经连成可靠流程。

## 16 项可实施补充

S 为本轮编号。P0 是近期基础补全，P1 是相邻功能扩展，P2 是需要模型研究的方向。每项都是本项目方案，来源提供需求线索，不是实现已经完成。

| 编号 | 方案 | 最小范围与验收门槛 |
| --- | --- | --- |
| S01 P0 | 完整配方保存 | 保存主题外观、局部环时钟／发射参数、暂停与相机；重开逐字段对照。首次先修 0.20.0 已明确未持久化的局部环参数，对应 Wiki W14 与原保存路线 |
| S02 P1 | 行星＋卫星子系统模板 | 保存相对状态与组内引用，新对象分配新 ID；预览整体移动／旋转，确认一个事务。检查组内距离、相对速度、质量、外观不变，超预算整组拒绝 |
| S03 P1 | 双星／双行星放置 | 明确两体总动量与质心速度，确认同时更新双方；质心标记无额外质量。当前小尺度数值限制解除前，不直接推出紧密地月级模板 |
| S04 P1 | 赤道／轨道／自定义平面 | 显示平面及顺逆行方向；输入、预览、确认使用同一坐标变换。旋转视角不改变初态，零倾角等退化情况有定义 |
| S05 P1 | 外观随天体保存 | 条纹、两层云、大气、环、种子和光照方案有完整配方；复制单个天体不丢气层，改变云层不改变重力质量 |
| S06 P0 | 展示与计算分别分档 | 环视觉质量不靠增加引力对象；标签、渲染点与真实半径区分。不同画质用同一初态时，物理采样保持一致 |
| S07 P1 | 可恢复的摄影模式 | 一次收起面板／标签／轨迹，保留可找回的退出入口；退出恢复原选择、相机和显示选项。旋转折叠时状态栏仍按沉浸规则处理 |
| S08 P1 | 原创实验包与版本预检 | 封面、观察目标、可调变量、模型要求、创建版本、种子、数据来源、作者／许可字段；不支持的模型先解释，不能静默更换 |
| S09 P0 | 查找与恢复已保存实验 | 搜索、最近保存时间、配方／回放类别和存储用量；保存完成后才显示成功。错误不覆盖原实验，新增云端能力前先保证本地可靠 |
| S10 P1 | 多选与碎片清理 | 列表／区域选择，显示数量，支持取消与作为一组撤销；已有对象编辑历史需扩展到批量事务，触摸与 CLI 结果一致 |
| S11 P0 | 小数与单位格式可靠 | 极小非零量显示科学计数或合适单位；切换单位不改变模型数值；显示四舍五入不得回写原始数据 |
| S12 P1 | 有效数据驱动图表 | 无有效新采样时保留上一次量程并标明状态，折叠／滚动不改单位；固定／自动量程显式选择。不是只锁住一个错误量程 |
| S13 P1 | 故事、操作与记录组成引导 | 每个实验 3–5 步，修改一个变量、观察一个指标、保存一个分支；能跳过和重来，完成条件绑定真实状态。承接 Wiki W01 |
| S14 P1 | 展示控制与场景连续 | 手机单主视口，宽屏按需显示精简控制；已有 CLI 共用动作可做讲解控制。外接屏与多窗口为待验证扩展，窗口变动不重置演算 |
| S15 P2 | 碰撞与捕获的模型分级 | 先守恒检查与单体平衡，再对照撞击角度、速度、质量比。无自引力的现有岩石 SPH 不作为月球形成；无耗散的两体飞掠不承诺永久捕获 |
| S16 P1 | 可复现的变体与来源 | 固定种子，分开记录原配方与用户改动；真实目录写历元，艺术调整有标记。标题叫“真实／全宇宙／100%生命”不提高科学可信度 |

## 下一批工作的具体范围

第一批先补 **S01、S06、S09、S11**：保存完整外观／局部环参数、画质与物理状态分离、可找回的存档、极小值显示。先使已有九个主题真正可重现，再扩展库的数量。

第二批做 **S02–05、S07、S13**：子系统草稿、平面放置、完整皮肤与摄影、分步引导。其中局部卫星和双行星要先解除当前初始最小间隔 0.05 AU、近遇停止 0.02 AU 对小尺度实验的限制，并建立适当步长与独立对照；不直接放宽限制后上线。

第三批沿已有路线补自引力和碰撞诊断，再开展 S15。当前 0.20.0 的 2–8 点质量轨道、无自引力的岩石 SPH、192 个无质量局部环示踪点是不同模型，不能把它们的画面拼接当成已经耦合。完整求解器检查点也不同于最近 240 帧可视化回放。

子系统保存的首版实现约束如下；这是待实现的数据设计，不是新增 CLI 已可调用：

1. 用组内稳定 ID 表示对象引用；导入时整体重映射，不用列表下标充当永久身份。
2. 记录明确的模型、单位、组参考位置与速度、每体相对状态、外观、种子和应用／配方版本。
3. 放置采用静态旋转 `R` 和整体平移／速度偏移，`r' = R·r_relative + r_origin`，`v' = R·v_relative + v_origin`；这里不引入旋转参考系附加速度，也不擅自缩放距离、质量或时间。
4. 预览不修改当前模型，确认一次提交；取消、超预算、失效引用、非法数值或版本不兼容都保持原场景。
5. 验证导出再导入的字段、组内距离与相对速度、撤销恢复、旧配方迁移；成功标准不能只比较截图。
6. 新动作进入 ArkUI／CLI 共用目录；模拟器按项目约定仅操作 `127.0.0.1:5555`。触摸命中、焦点、折叠和旋转另作实际验收。
