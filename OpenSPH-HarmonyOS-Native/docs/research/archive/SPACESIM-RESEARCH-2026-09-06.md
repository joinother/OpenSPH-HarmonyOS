# SpaceSim 网站与论坛调研：鸿蒙星体实验室的可借鉴方向

> 类型：调研快照；适用范围：历史方案。
> 调研日期：2026-09-06；整理日期：2026-09-06（Asia/Shanghai）。

本文保留当时的判断、限制和操作记录，可能已被后续版本替代。请先阅读[当前文档目录](../../README.md)。

调研日期：2026-09-06。对象为 Pavel Ševeček 的 SpaceSim（Steam App 4055380）。结论：优先完善“设计实验、运行、理解结果、保存复用”的流程；新增物理能力先评估 N-body 轨道与简化行星环。保留 ArkTS 界面和 C++ 求解器的现有分工。

本次阅读了作者官网、Steam 产品页与更新公告、公开 Lua 文档、性能解释文章及四个具体论坛主题。未进入 Discord 私密讨论；作者链接的 Miro 路线图未成功读取。没有运行 SpaceSim，因此产品行为依据公开资料，性能不是本机实测。以下明确区分官方事实、用户反馈和本项目建议。

## 查到的实际功能

作者确认 SpaceSim 使用 OpenSPH，主要改进面向普通用户的图形操作体验。上游 OpenSPH 原本侧重节点式科学实验配置。[作者官网](https://pavelsevecek.github.io/)

产品页列出：可变形天体与刚体、行星/恒星/小行星/盘/云/星系、材质与外观编辑、引力透镜、物理量着色、引力辅助线、历史回放、相机路径、CPU/GPU 求解和视频/数据导出。高粒子数计算可能耗时很长。[产品介绍](https://store.steampowered.com/app/4055380/SpaceSim__Astrophysical_Simulation_Software/)

本次公告中看到 8 月 8 日的 0.11 与 8 月 9 日的修补版。新增内容包括分析图表、参数联动锁定、教程、锁定相机、对象复用、渲染比例，以及仍有限制的恒星演化；修补版处理了续算与状态序列化问题。这些是公告确认的功能，不能直接等同于开源 OpenSPH 已提供的实现。[官方更新记录](https://steamcommunity.com/app/4055380/allnews/)

Lua 文档将扩展分成对象生成、每步物理系统、整个场景配置三类；使用 SI 单位，并提示部分字段文档不完整、非法参数可能造成不稳定。[官方脚本文档](https://pavelsevecek.github.io/lua.html)

## 与我们当前版本的差距

检查依据：本地 `OpenSPH-HarmonyOS-Native` 的 README、`engine.h` 和 `core/gravity` 源码。0.2.0 的 CLI/界面新增内容已通过构建与宿主测试，尚未完成本轮设备验收。

| 能力 | 目前情况 | 建议推进内容 | 优先级 |
| --- | --- | --- | --- |
| 天体编辑 | 三个固定实验、有限参数，半径固定 | 先支持两个岩质天体的名称、半径、密度/质量、位置、速度、自转；随后才扩大对象数量与材料 | P0 |
| 参数联动 | 没有质量/半径/密度编辑 | 球体中明确锁定哪个量、重新计算哪个量；变更预览和撤销；非球体使用对应体积模型 | P0 |
| 实验库 | 参数和回放分别单槽保存 | 项目缩略图、名称、说明、种子、模型版本；支持另存与复制 | P0 |
| 结果理解 | 速度/密度着色、几个即时数值 | 先画最大速度、平均密度随模拟时间变化的曲线，时间轴同步光标，再加守恒诊断 | P0 |
| 历史回放 | 最近 240 帧、按帧播放 | 按物理时间播放；标记截断范围；配置随回放保存；再做磁盘分块与区间导出 | P0 |
| 上手引导 | 三个场景卡、简短提示 | 选实验→改一个参数→运行→观察→保存，随时可跳过或重启 | P0 |
| 轨道与行星环 | 应用尚未接入；源码含 NBodySolver 和 BarnesHut | 两体轨道、三体、简化环；独立模型入口、轨迹与参考系 | P1 |
| 对象观察 | 跟踪两个原始天体的质心 | 统一对象选择、居中、持续跟随；碎裂后需另做碎片识别，不能把来源 ID 当新天体 ID | P1 |

## 下一阶段建议拆成三个可验收增量

**增量 A：可编辑、可保存的碰撞实验。** 将固定 Config 扩展为有版本的 SceneDefinition。先让用户修改现有两个岩质天体，集中校验输入，保存参数与随机种子；UI 和 CLI 共用同一个场景模型。验收时比较保存前后的所有参数及确定性结果，确保非法输入不破坏旧场景。手机使用单对象底部编辑面板；平板和 PC 使用侧栏。这是我们自己的布局方案。

**增量 B：可理解的结果与回放。** 现有 Frame 已保存模拟时间、最大速度、平均密度和总质量，可先提供这些量的历史序列，不必把全部粒子传给 ArkTS。增加图表与时间轴联动、按真实模拟时间播放、回放覆盖范围说明。保存文件绑定场景、单位和模型版本，解决载入回放后仍显示其他实验参数的歧义。视觉快照和能续算的检查点必须使用不同格式/能力标记；不能以“保存了粒子位置”宣称支持续算。

**增量 C：轨道实验。** 先评估已有 N-body 代码的依赖与鸿蒙行为，建立两体轨道的周期、能量和角动量误差基线，再加入三体与环。用于展示轨道的无质量测试粒子不包含自引力和互相碰撞，不应宣称能形成卫星。手机性能目标通过真机基准确定，不沿用桌面百万粒子的宣传数值。

每一增量都补 CLI 自动验收：准备完成、运行/暂停、状态查询、保存载入及失败路径。多端一致性优先保证同一实验定义和同一单位语义；布局按窗口空间调整。

## 本轮结论边界

本轮完成公开资料调研和实施优先级梳理，未改动求解代码或安装包。最强的借鉴价值是让实验更容易建立、更容易解释和复用。复杂天文现象可以成为长期内容，但应逐个证明物理适用性、计算成本和移动端交互，而不是一次暴露所有参数。
