# 开发与验收约定

- 开始功能工作前先读 [唯一执行路线](docs/reference/PRODUCT-ROADMAP.md)，按 R 工单顺序推进；一次只推进一张主工单，前置未通过不跳过。历史预研的优先级不另起队列，用户明确重排优先。交付报告写工单状态、用户新增可完成的步骤、测试与下一工单。

- 优先使用语义 CLI 操作应用。先查询 `listCommands`、`getUiState`，再使用 `uiAction`、`setUiValue` 或物理模型命令；普通导航、按钮、编辑、选项和回放控制不使用坐标点击。
- ArkUI 按钮和输入框必须与 CLI 共用动作实现。新增控件时同步补全动作目录、草稿状态和输入接口；缺失命令应补实现，不能用坐标自动化长期替代。
- 截图和布局树用于视觉验收；触摸／键盘注入只用于明确的手势、命中、焦点或键盘避让测试。CLI 验收不能声称验证了触摸命中或动画流畅度。
- 批处理使用 `--batch`；需要初始帧或完整计算时使用 `--wait-state` 或批次中的 `waitForState`。批次运行失败即停止，已经成功的步骤不会自动回滚。
- HDC 必须显式指定设备。本任务只操作 `127.0.0.1:5555`，不能操作其他任务使用的真机。
- 保留 `tests/cli_transport.test.mjs` 的按钮／输入绑定覆盖检查，以及 `scripts/test-ui-cli-emulator.mjs` 的真实设备状态核对。

## 文档维护

- 先查阅 [文档目录](docs/README.md) 和 [文档流程](docs/WORKFLOW.md)。当前规则直接更新到 README 与 CLI 指南，历史变化进入版本记录，不在当前指南末尾堆叠旧行为。
- 新验证证据放入 `docs/evidence/`，保留历史原始数据；移动文件时修复所有引用。
- 区分调研、验证、发布和整理日期，使用 ISO 日期及明确时区；未知日期写“未单独记录”，不从文件修改时间推算。保留外部来源日期和原始日志时间戳。
- 交付前运行 `python3 scripts/check-docs.py`，并人工核对当前行为、版本和证据。纯文档整理不重建应用、不覆盖已有版本产物。
